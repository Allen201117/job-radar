# 第三方代码与许可

本目录留存我们借鉴或依赖的开源项目的许可证。

## 为什么要有它

MIT 许可**唯一的强制要求**就是：在软件的所有副本或实质性部分中保留版权声明和许可全文。
把别人的代码抄进自己仓库 = 制作了一份副本，所以必须保留。不保留就是违反许可，
哪怕代码是免费的。（不需要开源我们自己的项目，也不需要标注每一处修改。）

## 当前情况

| 来源 | 用在哪 | 许可 | 怎么用的 |
|---|---|---|---|
| Radix UI | `components/ui/{tooltip,dropdown-menu,tabs,accordion}.tsx` | MIT | **npm 依赖**，只用其行为层（定位/焦点/键盘/aria），视觉全部自己写 |

## 加新的第三方代码时

- **装成 npm 依赖** → 许可随包分发，通常不用额外做什么；但如果它是 MIT 且我们大量借鉴了
  其源码写法，在文件顶部注明来源。
- **把源码抄进仓库** → 必须做两件事：① 在本目录放一份 `LICENSE-<项目名>.txt`（原文照抄）；
  ② 在抄入文件顶部写 `// Adapted from <项目> (<许可>) - Copyright (c) <版权方>`。

## 明确不能用的

| 项目 | 原因 |
|---|---|
| **Tailwind UI / Tailwind Plus** | **商业授权**，需付费。很多人误以为它是开源的——不是，不能抄 |
| **Aceternity UI** | 免费组件本体 MIT，但条款禁止把含其组件的衍生品拿去出售；且风格是赛博/玻璃拟态，与本产品的暖色编辑部调性冲突 |
| **Magic UI / Motion Primitives** | 许可没问题（MIT），但动效组件强依赖 `motion`（原 Framer Motion）包。本项目已有 GSAP，不再引第二个动画运行时 |
