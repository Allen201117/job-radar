# 源名里的「校招 / 实习」后缀：全集、下游影响与改名方案（2026-10-11 调研，未动线上数据）

> 来由：`docs/reviews/2026-10-11-insight-duplicate-profiles.md` §6 第 6 条「要不要从上游改源名」。
> 本文只有调研和方案。库里的数字是 2026-10-11 傍晚在真库上只读查出来的，执行前要重拉。

## 0. 一页结论

**现状**（上午那份报告写 56 条源 / 50 个名字 / 11,323 个在招岗；傍晚重拉少了一些，因为当天的迁移 313 / 314 改指套件时已经顺手把 3 条源的后缀去掉了）：

| | 数量 |
|---|---:|
| 公司名以「 校招」「 实习」结尾的源 | 53 条（启用 41） |
| 对应的岗位公司名 | 49 个 |
| 这些名字下的岗位 | 11,631 行：在招 11,246 / 已下架 385 |
| 全库校招、实习渠道的源 | 399 条，其中带后缀的 48 条（12%），其余 351 条本来就不带 |

**三个事实决定了方案：**

1. **后缀不只是重复信息，有两成是错的。** 带后缀名字下的 11,246 个在招岗，逐岗分类是校招 8,019 / 实习 836 / **社招 2,391**。「中国交建 校招」名下 1,638 个是社招岗、「曙光信息产业 校招」428 个、「中国人民保险 校招」282 个——北森一个租户的列表会把社招校招一起返回，源名却写死了「校招」。岗位卡上公司名写着「校招」、徽标写着「社会招聘」。
2. **去掉后缀在机械上是安全的**（全集核过，§3）：改名后撞唯一键 0 行、同一个岗位链接两行 0 行、同一个平台岗位编号两行都在招 0 组；必投清单归属 0 变化；用真实分类器对 11,246 行逐行算「改名前 / 改名后」，改判 0 行。
3. **「中文 + 英文尾巴」不能照同样的办法统一**（§5）：要动 84,617 个在招岗（全库 19%），会让 55 个名字的必投匹配失效，107 个名字的 logo 掉成色块，还有两家不同公司会并成一个名字。

**建议：只改带渠道后缀的这 53 条源，英文尾巴这次不动。**

## 2. 全集

### 2.1 怎么数的

- 源：Supabase `sources` 全表 1,730 行分页拉回本地，按「公司名以空白 + 校招 / 实习 / 社招 结尾」数。「社招」后缀全库 0 条。
- 岗位：香港库 `jobs` 按 `company` 聚合（2,581 个名字、在招 442,564 行），同一条规则。
- 漏网的写法：另用「校招 / 实习 / 社招 / 校园 / campus / intern / 应届 / graduate」在全部源名和岗位公司名里各扫一遍，不符合「空白 + 后缀」写法的只有 §1 第 3 条那两个。
- 每个带后缀的岗位行都有 `source_id`；在招的 11,246 行，源名与岗位公司名逐行相同。已下架里有 9 行挂的是迁移 313 / 314 已经改掉的旧名（中国电信国际 校招 1、和睦家医疗 实习 7、苏州凌志软件 校招 1）。

### 2.2 后缀是哪来的

代码里没有任何地方会给公司名拼后缀（缺口漏斗的校招车道、自动扩源、探活脚本都用清单名或抄已有源名）。53 条全是迁移里手写的：46 条是 2026-06 的探活批次（hotjob 41、北森 5，迁移 084~107），7 条是 2026-09 的三份迁移（228 / 259 / 260，hotjob 5、Moka 2）。2026-07 以后新接的 262 条校招、实习源里，只有这 7 条带后缀。

## 3. 改名会不会出事（全集核验）

### 3.1 同岗两行

把 55 个带后缀的名字和它们的本名放在一起（在招 21,902 行、其它状态 5,968 行），在库里按改名后的名字分组数：

### 3.3 招聘类型分类（最容易出事的一处）

两件事会碰到它：

- 分类器第 6 层是「公司名里有『实习』判实习、有『校招』判校招」，排在兜底判社招之前（`lib/china-keyword-expansion.js`）。
- 库里的触发器把公司名当分类依据：**改公司名的那一刻，这一行的分类会被清空，等回填任务重算**（`jobs-db/schema.sql` 的 `jobs_guard_recruitment_class`）。

所以要回答「重算出来会不会变」。做法：把 11,246 行在招岗的标题、链接、job_type、经验字段拉回本地，用仓库里真实的 `recruitmentCategory` / `hasExplicitRecruitmentType` 各算两遍（公司名带后缀 / 去后缀），正文按空算。没有正文时更多的行会走到第 6 层，所以这是改判行数的上界。

| | 改判 | 「类型明确」标记变化 |
|---|---:|---:|
| 带后缀的 11,246 行 | 0 | 0 |
| 「神州信息—AI实习生」「豪迈集团—职能实习生」861 行 | 0 | 0 |

原因是这些岗在更靠前的层就定了：hotjob 的链接带 `postType=campus|intern`，Moka 的路径带 `campus-recruitment`，北森的链接带 `/social/` 且自报招聘类别。

全库岗位公司名里含「校招」「实习」的只有这 49 + 2 个名字，改名后没有任何岗位能在第 6 层命中。

清空到重算之间，这批岗处于「还没算」：搜索按信号超集取候选（结果不错，候选略宽），带招聘类型筛选的精确总数会退成「N+」。全库现在「还没算」的在招岗是 513 行，改名会临时加 1.2 万行，回填任务手动触发后预计几分钟回落（回填耗时没实测）。

## 4. 方案（只去渠道后缀）

## 5. 为什么不建议这次连英文尾巴一起统一

按「中文在前、空白、后面全是英文数字」数：284 条源、235 个岗位公司名。再加上渠道后缀，一共 276 个名字会变。

| | 只去渠道后缀 | 连英文尾巴一起 |
|---|---:|---:|
| 会变的名字 | 55 | 276 |
| 源 | 53 条 | 302 条 |
| 在招岗 | 11,246 | 84,617（全库 19%） |
| 改名后并到一起的组 | 36 | 78；另有 159 个名字只是换个写法、不和谁并 |
| 必投清单：模式命中发生变化的名字 | 0 | 55 |
| 必投清单：`resolve_owner` 发生变化 | 0 | 108 处 |
| logo 从有变成没有 | 2 | 107 |
| 撞唯一键 / 同链接两行 | 0 / 0 | 0 / 0 |

- 海外必投清单的模式全是英文名（`%Danaher%`、`%Morgan Stanley%`）。「丹纳赫 Danaher」改成「丹纳赫」后这条就不命中了，这家公司在台账里会变成零源缺口，漏斗会去重复补源（迁移 225 壳牌就是这么长出影子源的）。要避免，得先给清单补 50 多条中文别名，那是在改北极星口径。
- 「沃尔沃 Volvo Cars」（85 个在招）和「沃尔沃 Volvo Group」（378 个在招）是两家公司，去尾巴后同名。
- 行业和公司类型是按名字里的关键词算的，英文尾巴里的 power / energy / bank 之类的词去掉后，分类可能跟着变。这一项没有逐个名字核。
- 还有 48 个名字是反过来写的（「Google 谷歌」「Amazon 亚马逊」「Microsoft 微软」），同一条规则管不到，要另定「留中文还是留英文」。
- 统一后会暴露一批真重复，和名字无关：「地平线」与「地平线 Horizon Robotics」两条源有 412 组在招岗标题地点相同，「云南白药」与「云南白药 YNBY」357 组，「宁德时代」与「宁德时代 CATL」48 组，「阳光电源」与「阳光电源 Sungrow」24 组。这是同一家公司接了两个入口，该按「停一条源」处理（同迁移 305 / 316），不是改名能解决的。

洞察画像这一层已经靠别名登记和每日体检兜住。如果以后只是嫌卡片上的英文尾巴不好看，更便宜的做法是在显示层去掉，不动库里的名字。

## 6. 没验证的部分

- 分类对拍没带正文。结论「改判 0 行」对「改名前后是否一致」成立（两遍只差公司名，正文只会让更多行在更早的层定下来）；但「重算结果是否等于库里现在存的值」只在那 861 行上对过（逐行相同），11,246 行没对。
- /today 单公司上限合并后，真实用户各少几张卡，没有重放过。要量的话用零漂移对拍那套办法（同一批召回行、两版公司名各放一遍）。
- 代码盘点里「读代码」的几项（撤岗范围、看门狗、hotjob 归属核对）没有另外跑实验。`lib/campus-zone.ts` 里有一个 NUL 字节，搜索工具把它当二进制跳过了，归属那一段是单独读的，其余部分没逐行看。
- `sources` 表上有没有我不知道的约束：只从数据反推——库里已有多条同名源（荣耀 Honor 3 条、中国电信国际 2 条），所以公司名上没有唯一约束。迁移写好后按惯例在真库上「事务 + 回滚」整份演练。
- 回填任务重算 1.2 万行要多久，没实测。
- 数字取自 10-11 傍晚一个时点，执行前重拉。

## 7. 顺带发现（都没动）

- 岗位卡的招聘类型徽标是在浏览器里拿「标题 + job_type + 摘要 + 链接」现算的（`components/JobCard.tsx`），调用时没有把库里存的分类列传进去。CLAUDE.md 里写的是「卡片徽标读列」。两者不一致时卡片和筛选结果会对不上，这次没量有多少行。
- 「广发证券 GF 校招」9 行、「TCL 实习」1 行在招岗超过 14 天没被列表抓到，探活也没把它们下架。
- 香港库的撤岗墓碑表里有 1,864 行带后缀的公司名。那是历史记录，不展示，不用改。
- §5 最后一条那四组「同一家公司两个入口」的重复源。
