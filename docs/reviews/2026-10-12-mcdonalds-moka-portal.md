# 麦当劳 Moka 门户：社招源只该留哪些岗（2026-10-12）

结论：社招源改成只抓门户按关键词「管培」筛出来的列表（迁移 327 + `MokaAdapter` 认源地址里的筛选）。
创始人同日同意（原话「按照你的建议来」）。校招源同日由迁移 326 停用，不在本文处置范围内，只记查到的事实。

## 1. 门户自己怎么说

社招门户 `social-recruitment/mcdchina/4610`（老版，每页 15 条）主文档内嵌数据：

- 门户名「麦当劳加入我们（餐厅）」，列表模块标题「餐厅职位」，自报在招 58,187 个。
- 按职能分组：门店类 57,319、其他 569、营运类 151、食品安全类 133、人事类 6、市场类 6、行政类 1、战略类 1、财务类 1。
- 按部门分组（合计 58,187）：带店号的门店 8,877 个部门 56,149 岗；「××-新店」24 个部门 1,005 岗；
  「CN …」区域 / 职能部门 74 个 130 岗；临时门店 4 岗；没挂部门 899 岗。

官网「加入我们」页分「查看餐厅雇员职位」「查看办公室雇员职位」两个入口，都是微信小程序码。
Moka 平台的无编号别名（`social-recruitment/mcdchina`、`apply/mcdchina`、`campus_apply/mcdchina`）只指向 4610 和 4328。

## 2. 门户的筛选参数

都是在页面上点选之后从地址栏读的，新开页面直接带参数同样生效：

| 筛选 | 地址里的写法 | 备注 |
|---|---|---|
| 职能 | `#/jobs?zhineng=<id>` | 单选；「其他」那一档是 `zhineng=0` |
| 部门 | `#/jobs?department=[id,id,…]` | JSON 数组；多个 id 是并集（2 个部门 2 + 2 = 4 条，74 个部门 130 条）；没挂部门是 `department="others"` |
| 关键词 | `#/jobs?keyword=<词>` | |

翻页是 `&page=N`。筛选后的列表约 1 秒一页，不筛约 3.3 秒一页。
筛出 0 条时列表区只有一句「尚无任何相关职位」、没有翻页器，右栏「最新职位」照样挂着 5 个不受筛选影响的岗。

## 7. 校招门户查到的事实

`campus-recruitment/mcdchina/4328` 自称「系统默认校园招聘门户」，34 个岗全标门店类，挂在广州 7 家店下：
餐厅员工、就业见习人员、退休人员、咖啡师、品牌大使，最后一次发布是 2023-11。库里这 34 行曾全部标成校招，
年限口径上线后已下架；这条源由迁移 326 停用。

官网 2026-09-23 的「IT 2027 届校园招聘」通告是图片，海报页脚写着「无忧工作网版权所有」；入口没有去找

它为什么前几轮没报、147055 的岗该归谁没有查。

## 9. 没验到的

- 带店号的 56,149 条门店岗没有逐条翻，按部门名和关键词条数判断。
- 见习经理、值班经理只有门户搜索给的总数。
- 筛选只在这一个老版门户上点过；新版门户的筛选地址长什么样没看，adapter 在新版门户上遇到带筛选的源会记失败。
- 「维持现状会越积越多」是按机制推的（新发布的岗把旧岗挤出前 75 页，Moka 没有按列表缺席下架），没量每天滚动多少。
- 本机试跑用的是系统 Chrome + 国内出口，CI 是自带 chromium + 境外出口，以线上抓取记录为准。
