## 6.1 执行摘要（给创始人，讲人话）

**一句话结论：管道全都在转，供给面基本够了，但「最后一公里」坏了——库里有货，用户拿不到、拿到的不对、点开的会死、看到的洞察三成有错。闭环是通的，价值在漏。**

### 最伤用户的 3 个问题

1. **「推给我的不对，对的又不推给我」——Today 推荐两头都在坏。**
   该推的岗 **89% 从未进入推荐引擎**（7 个真实用户画像实测，召回率最低 2.6%——原因是从 26 万岗里只按「谁最新」抽 900 条给引擎看，抽签抽不到就永远看不见，漏掉的包括用户手填目标公司字节的「AI产品经理」原词命中岗）；而真正展示出来的岗里 **68.6% 经人工判定不该出现**（搜「测试工程师」会推来 C++ 开发，因为任何工程师岗的 JD 里总有「测试」两个字；2026 年所有 JD 都写 AI，导致法务岗被判成产品岗推给 AI 产品用户）。而且 feed 永远显示满 20 张卡，**这两个问题在任何指标上都看不见**。

2. **「库里有，但你看不见 / 点不开」。**
   央国企其实抓通了——库里躺着 **1,008 个央企岗**，但用户搜「国家电网」是 **0 条**（岗挂在「国网xx子公司」全称下，品牌词搜索命不中，核名规则还把真子公司当同名混淆丢掉了 98%）。用户点开即死的岗约 **3%**，元凶不是撤岗漏检、而是 11 个飞书租户（商汤/Momenta/Pony.ai/拓竹…）关了门户但 API 还在吐岗——1,192 个必 404 的坏链岗陷入「删了→次日重抓→变新岗」循环，**永远顶在岗位库最前面**。另有 4,028 个页面已死的岗被探活器天天盖「已检查」的活章。

3. **「洞察在输出错误信息，而且供给线已经停了」。**
   30 条洞察人工核验：只有 30% 真有信息差，**27% 存在严重问题**（把行业新闻当公司洞察、把融资新闻当年终奖、把美的的上市交易所写错）。宣传的「样本≥5 + 两源共识」两道门是**构造性必过的假门**。同时 2026-08-25 起 LLM 账户欠费，洞察生产线全停，**但每天照常烧光 90 次搜索额度**（其中 serper 是一次性总额度）。

### 如果只做 3 件事

1. **【今天】给 SiliconFlow 充值**（用户外部动作），并加「LLM 失败即停」保险丝（<1 小时代码）——止住每天的纯净损耗。顺手把 4 个 10 分钟~半天级止血件一起做掉（探活漏排名单、审计超时参数、验收门 SPA 误杀——**这个 8/27 重试就会再删一次 872 个真岗，最急**）。
2. **【本周】召回+匹配小修包（约 1 周工作量，全是小改动）**：召回排序三项修复 + 预算 900→1800 + 校招「27届」一行修 + exact 档收紧三机制。实验已验证：召回率约 10.8%→25-35%，最差画像误报 -53%。这是把核心价值①从「名存实亡」修到「基本可用」的最短路径。
3. **【两周】央企子公司枚举 + 品牌别名归一（3-5 天）+ 洞察质量门实修（2-4 天）**：前者让「央国企没打通」的体感直接消失且北极星不再虚低；后者宁可洞察产出量 -30~50%，也不再把错的东西给用户。

### 一个比所有单点问题都值钱的发现

本轮确诊的重大问题——召回漏 89%、浏览器审计产能坍缩 27 天、暗死岗盖活章、快车道台账永远 queued、db-report 停摆 6 周——**共同点是：坏了很久、指标上全看不见**。「CI 绿灯 ≠ 有产出」在本项目已经第 N 次应验。建议把「每日真产出台账 + 告警」当成第七条主线来建（详见 §6.5）。

### 主线 B：召回覆盖（findings-B）

**实测**（2026-08-27 10:12 同一 REPEATABLE READ 快照，7 个真实画像，理论集=对 26.3 万行召回窗口逐行跑生产 `checkEligibility`）：

| 关键数字 | 值 |
|---|---|
| 召回率（微平均） | **10.8%**（逐画像 2.6% / 7.0% / 19.2% / 40.9% / 7.2% / 10.7% / 32.4%） |
| 每人「最好的 20 个岗」被召回数 | 平均 13.1/20（最差 5/20） |
| 漏因分解 | **73.0% 名额抽签落选** / 14.3% search_doc 不含正文的结构漏 / 1.9% 校招「27届」预筛误杀 |
| 900 名额换来可展示岗的效率 | 平均 **23%**（company 层存活仅 1.3–12.9%，cityNew 层 0–9.3%） |
| DB 时间对预算的敏感度 | 900→3600 仅 **+3%**（成本在传输 ~1.37KB/行与 JS，线性） |

**确诊**：① 召回本质是「候选宇宙里按时间抽签」——层内排序（城市命中→最新）与能否过 JS 门无关；② companyHit 不豁免 role 门（eligibility.ts:217/:231-234），company 层 ~180 名额九成召回必拒岗；③ scope=all 用户的 cityFirst 把海外可投岗沉底（画像E 漏 92.8%）；④ 校招 LIKE 预筛不含「届」（opportunities.ts:123-129），「-27届」标题岗被杀；⑤ feed 恒满 20 张 → 漏报零外显。
**证伪**：「900 预算贵/香港库扛不住」（DB 时间平坦）；「三层轮转有层饿死」（机制正确）；「大厂挤占是算法造成」（过门集中度与理论集同构=供给事实）；「漏报主要因 search_doc 缺正文」（结构漏仅 14.3%，排序抽签占 73%）。
**未验证**：SUMMARY_TRUNC=300 对匹配判档的杀伤量级；修复收益 25-35% 是外推（评测管线可复跑复测）。

### 主线 A：推荐准确性（findings-AE）

**实测**（6 个真实画像全链路重放，102 岗人工标注）：误报 **68.6%**；理论应展示 vs 实际展示的漏报 50%–92.6%；related 档仅占展示 11.3%；「≥3 维 unknown 放行」仅 0.1%。

**确诊**：误报大头在 **exact 档被三机制击穿**——① AND 单元「泛词靠标题、具体词撞正文」（china-keyword-expansion.js:400-428）；② classifyJobFunction 的 summary 兜底+例外回落，JD 提「AI/产品经理」就把 HR/法务岗判成研发/产品（:717-730）；③ 查询词组扩展退化成裸泛词（'数据中台'≡'数据'）。收紧实验已跑：最差画像误报 473→224（-53%），误伤 1-2%。另确诊：行业硬门用公司标签杀岗位（30% industry_mismatch，TCL 的 AI 产品岗被硬拒）；location 空但标题带「（长沙）」的岗绕过城市门；简历解析把证书/工具词灌进关键词（54% 用户偏好被污染，resume-parser.js:85 + resume/route.ts:457）；Today 硬门 vs Jobs 软打分大面积互相矛盾（单画像 347 个岗两边结论相反，Jobs 的「高匹配≥40 分」可零 role 命中凑出）。
**证伪**：「related 太松是主因」（仅 11.3%）；「四维 unknown 是常态」（0.1%）；「兄弟组排除逻辑有 bug」（脏在上游分类器）。

### 主线 E：筛选器（findings-AE）

**确诊**：① **省份/区域目标城市全链路字面匹配**——填「陕西」的用户 Today 基本不可用（西安 2,635 岗被硬拒；39 画像中 13% 中招）；② 城市浏览计数错 5 倍且结果为任意子集（北京 FTS 候选 41,572 > cap 8,000，截断无 ORDER BY）；③ FTS 路径把 28,238 个空 location 岗全排除，与 JS「缺失降级放行」设计矛盾（search.ts:106-117 注释的超集声明对 tsquery 路径不成立）；④ 两路径口径差六处（城市匹配两套函数、行业 Today 有硬门 Jobs 无此维度、exclude 6 字段 vs 2 字段、阈值互不换算）；⑤ 默认「匹配排序」只看最新 2.8 万行，计数实为「最新 2.8 万里的匹配数」。学历是唯一两路径完全一致的维度。
**E4（少步骤）**：jobType/城市/学历/地区都可从偏好与简历自动推断，建议默认带「按你的偏好筛选中」芯片+一键清除。

### 主线 C：岗位库全面性（findings-C）

**C1 央国企**：「源没插/adapter 坏/没进 CI/被扫死」全部证伪——28 个 iguopin 源全 enabled、每日在抓、库里 1,008 active（healthy≈968）。真相四层：快车道 CRAWL_DETAIL_CAP=0 与 `_detail_verified` 硬门冲突每轮 found=0；国聘搜索模糊且硬顶 ~400 行；核名把真子公司杀掉（南方电网抽样存活 0/100）；**入库了用户也搜不到**（子公司全称 vs 品牌 bigram 0 命中，北极星 pattern 同病→台账把国家电网记成 no_active_jobs）。修复路径已 live 验证：国聘 children-list 集团→子公司枚举接口匿名可用，子公司全名搜索干净（10/10）。
**C2 抓全率**：「头部爬得不够全」基本证伪——字节/腾讯/阿里/美团/百度/小米/京东/网易/B站/携程/OPPO 爬取日抓全率 94–100%（腾讯独立 live 复核 ✓）。真缺口只剩华为（healthy 率 47%）与拼多多社招（整条缺失）。**反向发现：8 家 DB active 反超官网 13–136%**（比亚迪 +3,400、京东 +1,450）= 死岗堆积，已与主线 D 互证。
**C3 缺口 114 家**：技术能打通 ≈65（含 5 家被自己 bug 卡住、zhiye.com 家族一 adapter 解锁 3 家、~30 家 SPA 等浏览器道、~8 家银行）；清单治理换人 ≈15（全部因「不公开招聘」，无一因抓不到，**待创始人拍板**）；人工介入 ≈34（含 4 家 entry 张冠李戴且 next_retry_at=None 永不重试）。
**C4 产能**：稳态新源 3–5 个/天（87% 靠 moka/beisen 猜租户），httpx 自动扩源已枯竭（3 天 0 产出=候选池耗尽，非误杀）。需求侧证据（39 注册用户）撑不起「扩到几万家」——短板是品牌可搜性+行业塌陷（传媒 37%/物流 43%/金融 50%），不是公司总数。
**C5 验收门**：**实锤误杀**——亿纬锂能 872 真岗因样本核验用 httpx 验 JS 渲染页失败被整体回滚删除（与 8/26 修的入口层误杀同病换层，**8/27 重试将重蹈**）；华泰证券 probe 打到 jquery.js 空转 32 次。四处断路复核：3.5/4 修好（样本层残留同类病），新发现「缓存 entry 无身份复核→张冠李戴永久粘住」+「anti_bot 无退避」。

### 主线 D：岗位可靠性（findings-D）

**实测**：never-checked **横盘不收敛**（77,633→77,289→77,704 三次同口径）；产能账日流入 ~4,082 vs 有效 drain 打平；新岗 76% 七天内首检但长尾拖 1-3 个月。
**三层探活**：httpx sweep 健康且**过配**（每天 40.8 万次、每岗每天重检 2.2 次、0 失败——历史三大病均未复发）；**浏览器审计产能坍缩 27 天无人发现**（07-29 起每晚 shard 被 90min 超时杀掉，日吞吐 11.8k→4.7k，SPA 岗轮检 17→37 天——never-checked 不收敛的直接原因；run 显示 cancelled 但无人看 job 级）；展示/点击层名存实亡（14 天实际拦截 ≈0）。**盲区**：11 个 adapter 12,775 岗三层全不覆盖 + successfactors 有探活器但漏排 sweep matrix（7,815 岗）= **2 万岗（5.4%）永不验证**。
**死链率**（330 条实测：生产同款信号+真浏览器渲染+租户列表 API 成员核验）：**展示态 ≈3.1%**（全是 feishu 坏链、真撤岗 0/160）；大盘随机 ≈4.9%（上界 ~8%）。**两个 P0**：feishu 11 租户 1,192 坏链岗「删→重抓→变新岗」循环重生顶在最前；wecruit 存量+东风域名注销共 **4,028 暗死岗被天天盖活章**（enrich_backlog.py L188-193 网络错误也盖 enrich_checked_at，无升级路径）。
**D4 absence 红线**：护栏全在位、华为 False 有测试钉死 ✓；feishu 全集性 live 对拍通过；**beisen 有前瞻坑**（PortalId 门户页级、多门户租户列表非全集——qilu-pharma「渲染在招 vs 列表缺席」实锤；现被 dry-run 挡着零损失，**开 apply 前必须逐租户对拍**）；bytedance 全集性本机网络够不着未验证（建议 CI 内对拍）。
**证伪**：「sweep 跑了等于没跑复发」「展示态死岗=撤岗检测失灵」「never-checked 恶性增长」「absence 在乱杀」。

### 主线 F：职业洞察（findings-F）

**覆盖**：active 洞察 6,164 条、505/1,162 家（43.5%）、按岗位数加权 51.7%；「58% 点开全空白」大部分证伪（T1 派生兜底后真空白仅 114 家）；但**覆盖与需求倒挂**——无洞察公司岗位量 Top15 全是大户（强生/长城/吉利/汇丰…），因 T3 队列按 founded_year 排序。产能 8 家/天，补齐 657 家 ≈82 天——前提是 LLM 活着。
**P0**：SiliconFlow 402 欠费，08-25 起 T3 全停、**每天照常烧光 90 次搜索额度**（检索先于 LLM；402 未入 account_error 分类）。
**质量**（30 条分层抽样）：真有信息差 30% / PR 套话 27% / **严重问题 27%**（含美的上市板块写错直达用户——Wikidata 上游错、巨潮名匹配漏掉未纠错）。**根因确诊**：「样本≥5 + ≥2 源共识」构造性必过（sample_size=检索条数 insight_backlog.py:325、publisher 按整包计 insight_engine.py:244、_pick_sources 凑未核验源 :241-253）；真正在拦的只有单源判官（42%），但它不校验公司/维度相关性。
**时效**：巡检真在跑且有效（30/30 天绿、active 零过期）——证伪「又旧」担忧；3 年窗有 ~5% 泄漏。
**合规**：✅ 无直爬社区/招聘平台路径；一处灰区待拍板（洞察引用 URL 出现 BOSS直聘/智联页面，搜索 API 前门返回、合规线内但观感有张力）。
**维度价值**：culture 41% 且 1/3 套话；path 被薪资内容污染；低成本新维度候选=面试流程轮次（查询包已有主题）、裁员/收缩信号（T1 已算 tightening 只是埋着）；真实薪资区间受限于 salary_text 仅 1.5% 有值。

## 6.5 我们认为你问错/漏问的问题

1. **「900 预算的瓶颈是什么」问错了方向**——预算根本不贵（900→3600 DB 时间只 +3%），真正的病是**排序与匹配无关**：73% 的漏报是排序抽签、只有 14.3% 是任务书最怀疑的「SQL 非超集」结构漏。修排序比扩预算便宜且有效十倍。
2. **「related 档太松」猜反了**——related 只贡献 11.3% 展示岗；误报大头在被三个机制击穿的 **exact 档**。按任务书原怀疑去收 related，误报几乎不会降。
3. **「1,162 家公司够不够」现在无法回答，也不必回答**——39 个注册用户的需求侧证据撑不起任何扩量结论。数据显示的真短板是「库里有但搜不到/行业塌陷」，先修这两个，扩量问题等有统计意义的用户量再问。
4. **真正该问但没问的：「我们的指标为什么看不见这些问题」**——本轮所有重大确诊（召回漏 89%、审计坍缩 27 天、暗死盖活章、快车道台账永 queued、db-report 停摆 6 周、absence 零日志）共同点是**静默**。建议立一条「可观测性主线」：① db-report 加每日 schedule 并进告警；② feed 加理论召回抽样率指标；③ CI 任务「run 级 cancelled/产出为 0 连续 N 天」告警；④ workflow 台账必须回写状态。这一条做好，本报告里一半的问题会在复发当天被看见，而不是 27 天后。
5. **一个顺带发现**：Today 路径的关键词匹配永远只见正文前 300 字（SUMMARY_TRUNC=300，正文 p50=390 字）——关键词在 300 字后的岗召回了也判不中。量级未测（未验证假设），P2 的正文 FTS 落地可顺带缓解。
6. **诚实边界**：本报告的误报率为单人标注（建议创始人抽 2 画像×20 岗复核，约 20 分钟）；召回率是同快照下界（按完整正文算理论集更大）；死链率的「判不了」9 条影响大盘数字 ±3pp；各修复收益预估须在实现后用同方法复测（B 线评测管线、A+E 线回归 harness 均已留存可复跑）。
